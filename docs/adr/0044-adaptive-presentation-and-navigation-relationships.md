# Adaptive presentation and navigation relationships

The previous interface could fit by stacking controls, but that did not establish
that their resulting form suited the user's activity. It also retained project
membership in the semantic tree without making that hierarchy legible in the
navigation. These are different failures from an overflowing rectangle.

Presentation form is independent from pane arrangement. A property can retain
its identity, complete observation and command while changing how much recognition
information is immediately visible. Frequent model identification remains visible;
reasoning detail can move to its existing chooser. Ordinary permission settings
can have a compact entry, but unavailable or consequential settings must retain
their explanation. Presentation does not change command availability or defaults.

The shipped Codex 26.1007.30912 uses its composer-footer container width for compact
labels, including a 475-pixel Electron threshold. That value provides an initial
reference calibration, scaled with our typography, rather than a universal law
about devices. The production decision uses the supporting region's actual
allocated inner width. A region that merely fits its current caption cannot
represent available space; this region therefore owns the residual slot. Full
and compact candidates are evaluated in the same bounded allocation decision,
before pane removal. Pane Capacity remains separate from physical form.

Interaction inertness does not remove a region from layout. An open menu still
leaves its composer allocated and visible behind it. Excluding that composer
from the width observation changed its form despite unchanged space. Layout
observation therefore retains inert regions; interaction and frame exposure
continue to apply their own foreground and focus rules.

The scaling operation takes its arithmetic capacity explicitly. Keeping that
parameter abstract in the universal scaling proof avoids expanding the pinned
checker's closed, large capacity calculation. Production still supplies the
existing capacity through its complete allocated observation; this changes
neither the bound nor the presentation decision, and needs no compiler override.

Navigation rows require stable content roles. Disclosure and identity, the title,
and trailing status or actions have different responsibilities. A growing title
must not relocate another row's status. Project membership calls for a common
group and subordinate child positions, derived from the semantic ancestor rather
than from coincidental label spacing. Long navigation labels can be elided while
retaining their complete accessible identity. A task that is active and idle is
ready for more work; a success-shaped completion mark would overstate that fact.

Independent tasks require a separate, named collection. Placing them immediately
after an expanded project implied membership that their actual state did not
contain. Their existing identities stay stable, while a collection boundary
communicates their scope. Stretching a navigation title also requires leading
content alignment: retaining generic button centering made its perceived left
edge depend on the length of the name rather than its membership depth.

Auxiliary actions should appear when their owning row is being used. Pointer
interest, focus within and ownership of an open menu are distinct from selection,
expansion and execution state. These observations belong to browser presentation,
not task execution or persisted preferences. Keeping the trailing geometry while
changing paint prevents revelation from moving the label. Keyboard focus and
non-hover input must expose the actions as well. The host interprets declared
observations and generic visibility; Bend decides the relationship between them
and the actual row.

The existing physical observation boundary equated an enabled command with a
visible, keyboard-reachable control. Contextual actions expose why these meanings
need independent representation: a command may remain valid while its entry is
concealed. Effective exposure therefore participates in observation and focus
requirements, including descendants of a concealed region. Retained geometry
continues to be checked; concealment cannot erase the expected element or change
its command availability. This also prevents a CSS-only visibility rule from
silently disagreeing with Bend's focus model.

Production correspondence establishes that these decisions preserve their objects
and commands. Browser inspection must additionally establish recognizable forms,
readable hierarchy, aligned rows, stable revelation and recovery when space
returns. Geometric feasibility alone cannot establish those outcomes.
