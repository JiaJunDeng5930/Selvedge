# 0046: Observation-backed activity construction

## Context

Property observations, decision admission, workspace collections, action
assessments and hierarchy geometry already provide useful local guarantees.
Composing their independent renderers did not establish which facts a user needs
for the current activity, which decisions depend on others, or whether a complete
editing activity has reached its commit boundary. Local containment also left
typography, interaction targets and floating reading measures independently
calibrated.

## Decision

Construct an activity from actual property, decision, collection and assessment
evidence. Interpret its constituent relations through a common presentation
path, and retain that activity on the outer surface where floating allocation is
decided. Domain factories determine prerequisites from domain observations;
browser construction consumes their relationships and reading demand together
with its existing hierarchy and physical constraints.

The original project and complete draft remain part of editing assessment so
that its completion boundary cannot be inferred from a rendered subset of
fields. Presentation projection retains the full model catalog because a query
is not a capability change.

## Rationale

Independent visibility and style flags would leave each caller responsible for
recreating the same relationships. Shared rendering alone would preserve that
problem while moving repeated markup. Observation-backed construction instead
keeps the decision basis and generated interaction together, and places the
activity's reading measure at the allocation boundary that can enforce it.

The calibration applies within activity surfaces. Other surfaces retain their
existing typography, limiting unrelated changes. Formal evidence concerns
production computations and semantic relationships; physical measurement,
platform behavior and perceived proportion still require their own verification.

Quantitative geometry takes the numeric capacity as an explicit input. Its laws
cover every capacity, while production callers supply the existing physical
ceiling. This avoids a second fixed-capacity wrapper and keeps the checked
operation identical to the operation used for construction. The distinction
matters because the pinned proof checker unfolds natural-number arithmetic
structurally, whereas native execution optimizes it; checking assembly must not
depend on evaluating a large closed ceiling through redundant wrappers.
