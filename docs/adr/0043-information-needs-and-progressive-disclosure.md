# Information needs and progressive disclosure

Status: accepted

The preceding property model retained ownership, effective values and sources, but
it presented nearly all of them whenever a control participated in an activity.
The user could not distinguish the message being written from the configuration
supporting that work. More truthful captions made that problem worse: every
control became a property card, and supporting content enlarged the empty editor.
The missing decision was why information should be visible at that moment.

We inspected the shipped Codex desktop static implementation in
`ChatGPT.app/Contents/Resources/app.asar`, package `openai-codex-electron`
26.1007.30912. Its composer separates the editor, header, model control, leading
and secondary actions, primary action and adaptive footer. Its permission control
uses the selected value and a state-dependent visual treatment. Its model setters
separate saved defaults, the current conversation and the next turn. These source
observations establish distinct responsibilities; they do not establish pixel
measurements or a universal placement rule for every Codex mode.

The chosen interface follows the user's activity. Recognition needs the effective
choice and enough identity to distinguish its owner. Evaluating an alternative
needs options and scope. Asking where a choice came from needs provenance. A
confirmed obstruction needs an explanation and repair beside the affected choice.
These needs come from the current action, property observation, owned interaction
intent and assessed requirements. A stored attribute alone is insufficient reason
to give it permanent visual prominence. Workflow frequency explains why common
choices remain compact and available; it is not an invented telemetry score.

A complete context observation must survive removing its former visible summary.
A passive semantic carrier can retain that observation while showing only the
current decision. Visibility is a projection of an observation, not deletion of
the observation or a reconstruction from displayed text.

Disclosure is owned by the interaction model so that opening an explanation cannot
change a draft, its effective choice or admission. External directory failure is
retained separately from ordinary rejection and directory browsing. Its correlation
to the submitted draft prevents an old result from becoming a current explanation.
An explicit retry allows an externally repaired directory to be observed again
without forcing the user to rewrite a message or change a valid choice.

Writing priority does not imply that the editor's minimum height must be twice a
supporting control's height. Text-line demand, operable target size and enclosure
clearance have different purposes. They are calibrated separately and bound to
actual production constructors. Native measurement remains responsible for the
height of entered text. Production proofs cover semantic correspondence; actual
browser inspection covers readability, placement, disclosure and focus.

The narrow-window inspection exposed a related boundary failure. A permission
summary was treated as an unbroken line, so opening navigation required 684 pixels
in a 632-pixel window. Breaking that whole string at arbitrary words also damaged
recognition: the model name and permission values became fragments. The selected
value and each consequential setting are separate, intact recognition units;
their group can change its arrangement without omitting a consequence or reducing
the font. A terminal asynchronous
measurement failure also retained the previous normal document, concealing why
accepted choices stopped appearing to change. Normal measurement completion now
uses the same bounded recovery path as initial construction, so an actual failure
cannot masquerade as an available interface.

The complete production verification entry checked successfully in 154,968 ms
with the pinned compiler and no diagnostic output. The former 60-second process
budget therefore rejected a successful verification before it could finish. The
default budget is now five minutes, retaining a finite bound and margin for local
load. Exit status, complete proof-success output and empty diagnostic output remain
mandatory; no proof requirement or compiler setting is relaxed.
