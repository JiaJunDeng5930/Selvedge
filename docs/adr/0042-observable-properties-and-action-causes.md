# Observable properties and action causes

Status: accepted

The first relationship model preserved object ownership and action scope, but the
closed controls still received presentation captions. A directory basename could
look like a project name, permission values disappeared behind a generic label,
and a valid absence looked like an unfinished mandatory choice. Retaining the
relationship in an intermediate value did not prevent its final projection from
discarding it.

Properties therefore retain domain observations and resolved resources behind an
owning interface. Browser faces read their title, value and source through that
interface. These are separate information roles because a user needs to recognize
both the object and its current state without opening every control. This follows
the distinction between [recognition and recall](https://www.nngroup.com/articles/recognition-and-recall/)
and the need for [visible system status](https://www.nngroup.com/articles/visibility-system-status/).

Submission assessment preserves concrete obstructions and their affected objects
and fields. The same pure readiness operation governs preparation and its visible
explanation; directory observation remains a distinct next step. This avoids
explaining an empty message with an unrelated configuration rule and avoids
performing external work for a known invalid draft.

Activity allocation connects writing priority to the actual editor and supporting
controls rather than to an arbitrary enclosing rectangle. Positive content
clearance also belongs to that construction. Formal evidence establishes the
production correspondence and allocation relationships; actual browser inspection
establishes whether their [visual hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)
is readable at the supported viewport sizes.

The preferred reading capacity previously also acted as a hard minimum for the
main area beside navigation. That conflated a comfortable reading target with
the minimum needed to keep an activity usable, and could prevent publication
after the viewport narrowed. Explicitly opened navigation now participates in
the same width budget; content measurement determines the remaining activity's
minimum. Property values stay intact while their supporting descriptions can
wrap at word boundaries.

Executable definitions and laws in `interaction/experience`, the interaction
assembly and browser appearance/control concepts express these relationships.

The message factory exposes measurement capacity as an explicit argument. Its
complete style correspondence holds for every capacity, and its production caller
retains the existing physical limit. This separates the universal construction
from evaluating a large concrete arithmetic expression inside the proof checker;
it also binds the actual message selection to the same specified factory.
