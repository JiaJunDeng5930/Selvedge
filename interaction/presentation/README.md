# Semantic presentation

Produces semantic page content and binds presentation composition and capabilities to the application.

The Work switcher uses the existing simultaneous-navigation capacity to choose a
desktop tab strip or `compact_header`: global menu, one current-Work/count target
and the Task-tree toggle. This choice is independent of sidebar visibility. Both
Work forms retain the same identity. Work overview uses ordinary modal layers
and actual Task summaries; selecting a card uses the same Work navigation.

`workspace_navigation` keeps the desktop rail and tabs. Narrow capacity instead
uses `GlobalNavigation` on the existing panel stack; its six destinations keep
their authoritative inputs. `compact_navigation` moves the unique header into
the expanded Task tree's modal scope, so its launchers remain usable. Closing
returns that same header to the base. Global menu and overview layers can cover
the tree and dismiss back to its real trigger. `task_navigation_creation` and
`navigation_contents` retain new conversation, Project groups and Task entries
without repeating global destinations. The presentation contract binds these
actual constructions and their native command identities.

Start with [MODEL.bend](MODEL.bend) for scene vocabulary and [SURFACE.bend](SURFACE.bend)
for nodes, gestures and surface vocabulary. [VIEW.bend](VIEW.bend) generates scenes;
[PROGRAM.bend](PROGRAM.bend) realizes surfaces and their interaction. These public
vocabularies remain independent of the computations that consume them.

Property decisions, collections and actions come from
[the experience operations](../experience/README.md). Their surface meanings
retain those constructions for browser interpretation and interaction binding.

[CONTRACT.bend](CONTRACT.bend) groups the presentation obligations by complete
responsibility. [scene-proof.bend](scene-proof.bend) provides semantic scene and
capability evidence; [interaction-proof.bend](interaction-proof.bend) provides
surface composition and interaction evidence. [PROOF.bend](PROOF.bend) retains
the whole-interface evidence needed by its clients. The repository
[PROOF.bend](../../PROOF.bend) imports all production providers.

[Experience](../experience/README.md) owns decisions, observed workspace collections
and action identity. The program derives alternative inputs and selection from a
single decision observation, resolves generated inputs through the application,
and attaches composer controls and feedback to the same action identity. The
complete construction obligations are `ExperienceRequirements` in the contract;
the existing composer, permission and submission obligations bind the surrounding
trees and native field payloads.

Closed composer controls retain an owner-built `Property`; `property_summary`
provides recognition and `property_source_nodes` reads the actual session source
intent for provenance. Field scope, current value and source share one observation. Creation
context places Project before Working directory outside the writing enclosure;
existing-task composition keeps that group absent.

`editor_scene` produces one `Assessment` from the draft, pending state and world.
The editor and composer carry that assessment into the passive action explanation
and canonical commit. `property_repair` and `subject_repair` correlate guidance
with the affected field; all obstructions remain in the assessment. The actual canonical control supplies final service availability. A distinct
unavailable reason restricts the same assessment; the commit and passive guidance
consume that restriction without reconstructing service guards. The complete tree and interaction equations in the contract
bind these constructions to the actual producers.

`CompositionRequirements` also binds the expanded and collapsed navigation
placement selected by `VIEW.navigation_placement`; the shell consumes that scene
placement through its authored assembly obligations.

Navigation distinguishes project membership from the collection of tasks without
a project. Project members remain children of their project group; independent
tasks retain their existing task identities inside a separately titled collection.
`navigation_declaration` retains each resolved declaration's identity, meaning and
availability while assigning `NavigationEntry` its route-derived selection.
`navigation_contents` assembles these destinations in a `NavigationSection` and
places navigation groups in a `NavigationCollection`; the header toggle remains
outside that collection. The independent-task section uses `NavigationCaption`
and preserves the original task parents, so its title does not introduce project
membership. `ProjectInteractionRequirements` binds these complete production
constructions, including empty independent-task collections and collapsed navigation.

The model menu, execution policy menu and project editor are produced through
`PROGRAM.activity_nodes`. Their domain factories supply the complete observations
to the controlled `experience/ACTIVITY` constructors; the interpreter consumes the
original relation tree through its public fold. The outer menu or dialog retains
both that activity and its real dismissal behavior. Decision focus belongs to the
session layer, separately from search and source disclosure, and the activity
checks the focused subject against its retained decisions before expanding choices.

`PROGRAM.activity_current_view` admits the session's real requested decision and
inspection state through `experience/ACTIVITY.view`. The common relation fold
consumes `relation_view_exposure`; required properties consume
`coverage_expressions` for each retained subject. Selected subjects construct the
actual canonical candidates, owned parameters construct their recognizable entry,
and permission consequences use the retained context and candidate's canonical
reviewer choice. Inspection facts reuse existing expressions only when the same
subject is actually presented; equal text is not a coverage criterion.

`activity_nodes` consumes the common completion boundary for Back, open-parameter
Apply and principal selection. A requested parameter keeps its declared native
`Edit` entry, reads the session buffer and dispatches whole-value completion through
the session's canonical model admission. Compound project editing keeps saved
object identity separate from the full draft Name field and retains collection and
assessment operations; Cancel uses the owning dismissal operation. Actual
`ActivityRow` wrappers preserve each descendant's meaning and binding for the
browser's shared row construction.

`activity_goal_label` consumes the activity's retained purpose. Compound editing
preserves the actual editor activity title; comparison and inspection express
owner and parameter through their existing subject coverage without repeating an
outer title. `OriginalIdentity` emits the retained saved resource as supporting
context and the independent full-draft Name field. A new object emits no invented
original identity. The layer/focus equations continue to retain this actual label
together with the same key, dismissal meaning and children.

Requested facts use `activity_readonly_field`: the retained Subject supplies an
explicit FieldLabel and the same editor/field owns the existing DisplayOnly Edit
value. This prevents bare state text from losing the property it describes.
DisplayOnly parameter views use this same construction; finite requested choices
receive their actual Subject caption. Principal choices add no requested caption.
Inspection coverage is only omitted for the same Subject when the actual
summary/control already supplies its descriptor. Scope and source sentences remain
supporting context, rather than extra initial property fields.

Terminal rows are constructed only at the actual completion affordance: the
compound terminal retains canonical commit plus owning dismissal, and the open
parameter terminal retains whole-value completion. The relation interpreter also
requires the activity's actual completion boundary before producing a compound
commit. Collection Add/Clear/Browse remain the owning draft's ordinary toolbar;
feedback remains supporting information. Back and inspection return are navigation,
not synthetic commit stages.

Expanded views retain the same activity identity as the layer's accessible name.
`activity_current_view` and completion determine one shared navigation header:
principal choices have no extra commit or heading, dependent views name their
actual subject, inspection names its property, and compound editing keeps its
existing object title and commit/discard boundary. The header retains the actual
`LeaveDecision` input; it is not inferred from a caption. The authored layer
recognizes this header and does not add a duplicate outer title.

The coverage fold consumes `ACTIVITY.information_expressions` and the actual
`information_status`. Inapplicable observations are normally absent; an explicit
inspection request receives an explanation instead of an editable control.
Required absence is attached to the subject's retained expression, while optional
absence remains an ordinary state. Scope remains supporting context in a settings inspection. Provenance has its
own explicit subactivity: the source entry retains the actual owner panel,
`PropertySource` resolves that owner observation, and the shared navigation header
uses the existing layer-stack return. Model, permission and project settings
therefore share source disclosure without another layer-state field or an
implicit native browser toggle. Detailed source descriptions occur only in that
requested subactivity.

`SettingEntry` preserves its original subject, current value and admitted input.
It is shared by dependent decisions and parameter summaries. Browser authorship
interprets these roles as a leading label, trailing current value and disclosure
inside the original whole-row native button, rather than parsing a joined string.
